# Задача: подвкладки в разделе «Контент» админки — «Контент» и «Метадані (SEO)»

Проект VRK Partners (Next.js App Router, лендинг uk-UA, админка shadcn/ui). Сейчас вкладка «Контент» редактирует тексты лендинга, а метаданные страницы (title, description, Open Graph и т.д.) захардкожены в коде (`config/site.ts` → metadata в layout/page). Клиент — не программист; он должен уметь менять метаданные из админки так же, как контент.

## 1. Подвкладки

Внутри страницы `/admin/content` сделать две подвкладки (Tabs — компонент уже есть в ui/):

- **«Контент»** — текущий редактор, без изменений.
- **«Метадані (SEO)»** — новый редактор метаданных.

Активная подвкладка — в URL (`?tab=meta` или сегмент), чтобы переживала перезагрузку. Вкладка «Юридичні документи» в сайдбаре не трогается.

## 2. Что редактируется в «Метадані (SEO)»

Посмотри, какие метаданные реально формируются в коде (layout/page metadata, OG, JSON-LD Organization), и выведи в редактор группами-карточками:

**Группа «Пошукова видача (Google)»:**
- Title сторінки — с живым счётчиком символов и подсказкой нормы (до ~60);
- Description — счётчик, норма до ~160;
- **Живой предпросмотр сниппета Google** под полями: синий заголовок, зелёный URL, серый текст — обновляется при вводе. Это главный элемент, который делает вкладку понятной неспециалисту.

**Группа «Соцмережі (Open Graph)»:**
- OG Title, OG Description (по умолчанию наследуют основные — показать это в UI: «Якщо порожньо — використовується заголовок вище»);
- OG Image — URL картинки с превью и валидацией хоста (тот же allowlist, что для картинок контента); подсказка про размер 1200×630;
- **Предпросмотр карточки шаринга** (как выглядит ссылка в Telegram/Facebook).

**Группа «Дані організації (JSON-LD)»** — только простые поля, которые уже есть в JSON-LD: назва компанії, опис, телефон, email, соцпосилання. Технические поля (тип схемы и т.п.) НЕ выводить.

**НЕ выводить в редактор:** robots/noindex (страницы /thanks и /admin должны остаться noindex — это инвариант), верификационные токены Google/Bing (env), canonical/URL сайта (env `NEXT_PUBLIC_SITE_URL`). Ничего из этого пользователь сломать не должен.

## 3. Подсказки для неспециалиста (обязательная часть)

- Вверху вкладки — короткий вводный блок: «Метадані — це те, як ваш сайт виглядає у Google та під час пересилання посилання у месенджерах і соцмережах. Вони не видимі на самій сторінці. Зміни застосовуються одразу, без деплою. Google може оновити свою видачу за кілька днів або тижнів — це нормально.»
- У КАЖДОГО поля — human-readable подпись + подсказка в одну-две фразы простым языком (что это, где отображается, что будет, если оставить пустым). Тултипы или постоянный серый текст под полем — как во вкладке «Контент», консистентно.
- Подсказки-«нормы» у счётчиков: зелёный в пределах нормы, оранжевый при превышении (не блокировать сохранение — только предупреждать: «Google обріже текст у видачі»).
- Все тексты подсказок — uk-UA.

## 4. Хранение и API — по существующему паттерну

1. Дефолты — из `config/site.ts` (текущие значения metadata). Оверрайды — в БД тем же механизмом, что контент лендинга (landing_content/site_settings — сделать единообразно с контентом). Fail-safe: ошибка БД → дефолты из кода.
2. Metadata лендинга (`generateMetadata`/layout) читает merged-значения (дефолт + оверрайд) — правки из админки реально попадают в `<head>` и JSON-LD. `revalidatePath` после сохранения.
3. API: тот же роут/паттерн, что PUT content (или соседний), право `manage_content`, Zod-валидация (длины полей — мягкие лимиты по максимуму разумного, например 200/500; URL картинки — по allowlist хостов; email/телефон — формат), whitelist полей, plain-text (экранирование как в остальном контенте).
4. Диф-семантика как у контента: сохранять только отличия от дефолтов (чтобы правки дефолтов в коде продолжали попадать на прод, если поле не переопределено).

## 5. Чего НЕ делать

- Не менять существующую вкладку «Контент» (кроме оборачивания в Tabs).
- Не добавлять новые зависимости (превью сниппета/карточки — простая вёрстка руками).
- Не давать редактировать robots, canonical, verification, hreflang и прочие технические вещи.
- JSON-LD рендерится как раньше (статичный, экранированный) — только значения берутся из merged-конфига.

## Проверка

1. `npm run build`, линт, `npm test` — зелёные.
2. Smoke: правка Title в админке → после сохранения `<title>` на лендинге обновился (view-source), OG-теги и JSON-LD — тоже; пустые OG-поля наследуют основные; невалидный URL картинки не сохраняется с понятной ошибкой uk-UA; пользователь без manage_content получает 403; при недоступной БД лендинг рендерит дефолтные метаданные.
3. Предпросмотры сниппета и карточки обновляются при вводе; счётчики меняют цвет.
4. /thanks и /admin остались noindex.
5. В отчёте: список редактируемых полей, где хранятся оверрайды, скрин/описание вкладки.
