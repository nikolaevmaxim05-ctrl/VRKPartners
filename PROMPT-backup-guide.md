# Задача: написать для клиента пошаговую инструкцию «Как выгрузить всё себе на компьютер» (бэкап)

Проект VRK Partners (Next.js на Vercel, БД/Auth/Storage — Supabase, код — GitHub, конверсии — Google Sheets). Клиент — НЕ программист. Нужен документ, по которому он сам, без разработчика, сможет скачать локальную копию всего, что принадлежит его сайту.

## Деливерабл

Файл `docs/INSTRUKTSIYA-BACKUP.md` в репозитории. Язык — украинский (uk-UA), как весь клиентский контент. Стиль — «для человека, который умеет пользоваться браузером, и не более»: короткие нумерованные шаги, каждый шаг = одно действие («Відкрийте…», «Натисніть кнопку…», «Оберіть…»), с указанием, как выглядит кнопка/пункт меню и что появится после клика. Без жаргона; каждый неизбежный термин (репозиторій, дамп бази) — объяснить в одну строку при первом употреблении.

## Перед написанием — сверься с реальностью проекта

Не пиши по памяти «как обычно в Supabase/Vercel» — проверь по коду и конфигам, что именно есть в ЭТОМ проекте, и пиши конкретно: имя репозитория GitHub, название проекта Vercel и Supabase (ref из CLAUDE.md/env), какие таблицы главные (leads, lead_comments, offline_conversions, site_settings, integrations…), есть ли storage-bucket (картинки контента), есть ли выгрузка Excel в админке (export_data / exceljs — проверь, какие разделы умеют экспорт). Если каких-то путей в UI сервисов не знаешь точно — сформулируй шаг по цели («знайдіть розділ Backups у меню Database») а не выдумывай точные названия кнопок, и пометь в отчёте, какие шаги стоит проверить руками.

## Что должна покрывать инструкция (разделы)

Для каждого раздела: зачем это сохранять (одно предложение), сколько времени займёт, пошагово как скачать, что получится в итоге (какой файл/папка), куда положить.

1. **Код сайта (GitHub)** — самый простой путь: зелёная кнопка Code → Download ZIP. Плюс одно предложение: «повна копія з історією — через git clone, це для розробника».
2. **База даних (Supabase)** — главное: лиды, настройки, контент, пользователи админки. Дать самый простой доступный путь (Dashboard → Database → Backups, если тариф позволяет; иначе — точная copy-paste команда `pg_dump`/`supabase db dump` с пояснением, откуда взять connection string и куда её подставить — буквально «замініть ТУТ_ПАРОЛЬ на…»). Отдельно: НЕ пугаться, файл дампа нечитабельный — это нормально, он для восстановления.
3. **Заявки (ліди) в зручному вигляді** — если в админке есть экспорт в Excel: как выгрузить все лиды/конверсии в .xlsx (это «человеческая» копия вдобавок к дампу). Проверь по коду, какие разделы экспортируются, и опиши каждый.
4. **Файли/зображення (Supabase Storage)** — если bucket используется: как скачать файлы через Dashboard → Storage.
5. **Налаштування хостингу (Vercel)** — env-переменные: Settings → Environment Variables, как их скопировать/выписать; предупреждение жирным: це секрети, зберігати у менеджері паролів, не пересилати поштою/месенджером.
6. **Таблиця конверсій (Google Sheets)** — Файл → Завантажити → Excel.
7. **Налаштування інтеграцій в адмінці** — ключи Telegram/KeyCRM/SMTP и т.д. хранятся зашифрованными; объяснить: их не «скачивают», а выписывают из первоисточников (BotFather, кабинет KeyCRM, Google) в менеджер паролей; сослаться на HANDOVER-checklist.md, если он в репо.
8. **Як часто робити бекап** — простая рекомендация: перед будь-якими великими змінами + раз на місяць; дамп БД — найважливіше (там заявки).
9. **Фінальний чек-лист** — таблица «що / файл / коли востаннє завантажено», которую клиент может заполнять.

## Оформление

- В начале документа — блок «Що взагалі зберігаємо і навіщо» на 4–5 строк простым языком (сайт складається з коду, бази даних із заявками, налаштувань хостингу…).
- Нумерация шагов внутри разделов, жирным — названия кнопок/пунктов меню, `моноширинним` — команды и то, что нужно вставлять.
- Предупреждения (секреты, «не діліться цим файлом») — отдельными выделенными строками «⚠️ Увага: …».
- Никакого HTML, только Markdown; документ должен нормально читаться и на GitHub, и в любом редакторе.

## Чего НЕ делать

- Не писать инструкцию по ПЕРЕНОСУ аккаунтов (для этого есть HANDOVER-checklist.md) — только скачивание копий.
- Не вставлять в документ реальные секреты, пароли, connection strings — только плейсхолдеры вида `ВАШ_ПАРОЛЬ`.
- Не предлагать сторонние сервисы-бэкаперы.

## Проверка

1. Файл лежит в `docs/`, добавлен в git; `npm run build` не затронут.
2. Самопроверка текста: пройдись по каждому шагу глазами новичка — нет ли шага, который требует знаний, не объяснённых выше по тексту; все термины объяснены при первом употреблении.
3. В отчёте: список разделов, какие шаги написаны «по цели» (не проверены в UI сервиса) и их стоит прокликать руками, и предложение — где в админке можно дать ссылку на эту инструкцию (например, в разделе «Налаштування»), НЕ реализовывая это сейчас.
