# Задача: привести вкладку «Юридичні документи» в админке к виду вкладки «Контент»

Проект VRK Partners, админка. Сейчас редактор юридических документов (`/admin` → «Юридичні документи», два документа: «Політика конфіденційності» и «Публічна оферта») — это плоская простыня одинаковых белых карточек «Заголовок розділу N + Абзаци + Пункти переліку», всё раскрыто сразу, десятки полей подряд, уровни не различаются визуально. А вкладка «Контент» («Контент лендингу») сделана удобно: секции — сворачиваемые блоки-аккордеоны с заголовком и шевроном, внутри — подписанные поля, иерархия читается.

## Что нужно

Переработать UI вкладки «Юридичні документи», взяв за образец вкладку «Контент» (найди её компонент — content-form и связанные — и переиспользуй те же компоненты/паттерны, а не пиши параллельную реализацию):

1. **Аккордеоны для разделов.** Каждый раздел документа — сворачиваемый блок, как «Перший екран (Hero)» во вкладке «Контент»: в шапке блока — номер и заголовок раздела (живой, из поля «Заголовок», обновляется при редактировании) + шеврон. По умолчанию все разделы свёрнуты — виден компактный список разделов документа; открывается один клик по шапке.
2. **Визуальная иерархия уровней вложенности — цветом**, в том же духе, что во вкладке «Контент»: уровень документа (переключатель «Політика/Оферта») → раздел (шапка блока с фоном/акцентной полосой слева) → поля внутри (заголовок раздела, абзацы, пункты переліку) с отступом и более светлым фоном подложки. Уровни должны различаться с одного взгляда (например, акцентная левая рамка/фон шапки раздела и приглушённая подложка для группы «Пункти переліку»). Используй существующие цвета/токены админки — ничего кричащего, консистентно с «Контентом».
3. **Управление разделами остаётся:** стрелки вверх/вниз (перемещение), удаление, добавление раздела — перенести в шапку блока/низ списка, как удобнее по образцу «Контента». При перемещении/удалении свёрнутое состояние остальных не сбрасывается.
4. **Ничего не менять в данных и API:** структура секций, эндпоинты, права manage_content, валидация, revalidate — как есть. Это чисто UI-правка. Логика «кожен рядок — окремий абзац» в textarea сохраняется, подписи полей сохраняются.
5. Описание сверху страницы («Зміни застосовуються одразу…») оставить. Кнопка сохранения — как во вкладке «Контент» (та же позиция/поведение, состояние «есть несохранённые изменения», если оно там есть — повтори).
6. Мобильная/узкая ширина: аккордеоны работают, ничего не разъезжается.

## Проверка

1. `npm run build`, линт, `npm test` — зелёные.
2. Smoke в админке: разделы сворачиваются/разворачиваются; заголовок в шапке блока обновляется при вводе; перемещение/удаление/добавление работает; сохранение применяется на страницы документов как раньше; вкладка «Контент» не затронута (если переиспользовал её компоненты — проверь, что она выглядит и работает как прежде).
3. Визуально: вкладка «Юридичні документи» ощущается как «Контент» — те же карточки, шрифты, отступы; вложенность различается цветом/фоном.
4. В отчёте: какие компоненты переиспользованы из content-form, что добавлено нового, скрин/описание итогового вида.
