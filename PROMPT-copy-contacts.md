# Задача: клик по телефону/почте — копирование в буфер + уведомление, с сохранением tel:/mailto:

Проект VRK Partners (Next.js App Router, лендинг + админка-CRM, UI лендинга и админки — uk-UA).

## Что нужно

Везде, где отображаются телефон и email (и на лендинге, и в админке), клик по ним должен:

1. **Копировать значение в буфер обмена** и показывать короткое уведомление (toast) «Скопійовано» рядом с местом клика или в углу экрана.
2. **Не отменять переход по ссылке**: элемент остаётся `<a href="tel:...">` / `<a href="mailto:...">`, `preventDefault` НЕ вызывать. На телефоне это откроет звонилку/почтовое приложение как обычно, на ПК — сработает копирование (и системный обработчик ссылки, если он есть). Оба действия происходят одновременно.
3. Никакого user-agent-детекта «ПК vs мобильный» — поведение одно и то же, различие даёт сам браузер/ОС через обработку tel:/mailto:.

## Где применить

Сначала найди ВСЕ места вывода телефона и email, затем примени компонент везде:

- **Лендинг:** шапка, футер, секция контактов — все места, где телефон/почта выводятся текстом или ссылкой. Учти, что контакты могут приходить из контент-оверрайдов/настроек (useContent / site_settings), а не только из config — компонент должен работать с любым источником значения.
- **Админка (CRM):** телефон и email лида в списке лидов и в карточке лида (lead-detail). Там для менеджера копирование — основной сценарий.

## Как реализовать

1. Один переиспользуемый компонент, например `<CopyContactLink value={...} type="phone" | "email" href={...}>`, плюс хук `useCopyToClipboard`:
   - копирование через `navigator.clipboard.writeText` с fallback (скрытый textarea + `document.execCommand('copy')`) для не-secure контекстов;
   - ошибку копирования не показывать пользователю как сбой — просто не показывать toast (переход по ссылке всё равно сработает).
2. **Что именно копируется:**
   - телефон — в чистом виде для набора: `+380XXXXXXXXX` (без маски/пробелов/скобок), даже если на экране показана маска;
   - email — как есть, в нижнем регистре, без пробелов.
3. **Toast:** сначала проверь, есть ли в проекте готовая система уведомлений (sonner, react-hot-toast, свой Toast в админке) — если есть, переиспользуй её; если нет — сделай минимальный собственный toast (портал, автоскрытие ~2 сек, без внешних зависимостей). Текст: «Скопійовано» (uk-UA), при желании с самим значением: «Скопійовано: +380…». На лендинге toast должен быть лёгким и не тянуть тяжёлых либ в клиентский бандл лендинга.
4. **Доступность:** элемент остаётся ссылкой (работает с клавиатуры), уведомление — с `role="status"` / `aria-live="polite"`; `title`/подсказка «Натисніть, щоб скопіювати» — по желанию, не обязательно.
5. **Аналитика:** если на кликах по контактам уже висят track()-события (клик по телефону/почте) — не сломай и не задублируй их; копирование добавляется рядом, существующие события сохраняются. Новые track()-события добавляй только если они есть в реестре аналитики (в проекте контракт-тест на имена событий).
6. Не менять существующую вёрстку/стили контактов заметно: визуально всё выглядит как раньше, добавляется только поведение (можно добавить курсор/иконку копирования в админке, на лендинге — без визуального шума).

## Проверка

1. `npm run build`, линт, существующие тесты — зелёные (включая контракт-тест аналитики).
2. Ручной smoke:
   - лендинг, десктоп: клик по телефону в шапке/футере → «Скопійовано», в буфере `+380…` без маски; клик по email → скопирован email;
   - ссылки остались `tel:`/`mailto:` (проверить href в DOM) и переход не заблокирован;
   - админка: копирование работает в списке лидов и в карточке лида;
   - лендинг открыт по http (не-secure контекст, если применимо локально) — fallback-копирование не роняет страницу.
3. Юнит-тест на хук/утилиту нормализации копируемого телефона (маска → E.164).

В конце — краткий отчёт: список всех мест, где применён компонент, и что проверено.
