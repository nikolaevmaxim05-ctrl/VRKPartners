# Як зберегти копію сайту собі на комп'ютер (резервне копіювання)

Ця інструкція — для власника сайту, а не для програміста. Досить уміти
користуватися браузером. Кожен крок — одна дія. Складні слова пояснені при першій
згадці.

## Що взагалі зберігаємо і навіщо

Ваш сайт складається з кількох частин, які живуть у різних сервісах:

- **Код сайту** — самі файли сторінок (на GitHub).
- **База даних** — сюди падають заявки з форми, а також контент, налаштування й
  доступи адмінки (на Supabase). Це найважливіше — тут ваші клієнти.
- **Файли/зображення**, які ви завантажували в адмінці (на Supabase).
- **Налаштування хостингу** — секретні ключі, завдяки яким сайт працює (на Vercel).
- **Таблиця конверсій** для Google Ads (у Google Таблицях).

«Бекап» (backup) — це копія цих частин у вас на комп'ютері. Якщо з сервісом щось
станеться (заблокують акаунт, зникнуть дані), у вас залишиться власна копія.

> ⚠️ **Увага:** ця інструкція — лише про **скачування копій**. Перенесення сайту на
> інші акаунти — це інша інструкція, `HANDOVER-checklist.md`.

Далі — назви ваших проєктів у сервісах (звіряйтеся з ними; якщо назва трохи інша —
шукайте свій єдиний проєкт у списку):

- GitHub — репозиторій **VRKPartners** (репозиторій = папка з кодом на GitHub).
- Vercel — проєкт сайту, відкривається за адресою **vrk-partners-nine.vercel.app**.
- Supabase — проєкт **«vrk proj»**.
- Supabase Storage — сховище файлів, «кошик» (bucket) називається **content**.

---

## 1. Код сайту (GitHub)

**Навіщо:** щоб мати всі файли сайту в себе. **Час:** 1 хвилина.

1. Відкрийте у браузері сторінку вашого репозиторію на GitHub (адреса виду
   `github.com/ВАШ-АКАУНТ/VRKPartners`).
2. Знайдіть зелену кнопку **`< > Code`** (справа над списком файлів). Натисніть її.
3. У віконці, що випаде, натисніть **Download ZIP**.
4. Браузер завантажить файл **`VRKPartners-main.zip`** (або `-master.zip`).

**Що вийде:** один ZIP-архів з усіма файлами коду. Покладіть його у свою папку
бекапів (наприклад, `Бекапи сайту / 2026-07 / код`).

> Повна копія з усією історією змін робиться командою `git clone` — це вже для
> розробника, вам для збереження достатньо ZIP.

## 2. База даних (Supabase) — найважливіше

**Навіщо:** тут заявки, контент, налаштування та доступи адмінки. **Час:** 3–5 хвилин.

Є два способи. Спробуйте спочатку спосіб А — він простіший.

### Спосіб А — вбудований бекап у Supabase

1. Відкрийте **supabase.com**, увійдіть у свій акаунт і виберіть проєкт **«vrk proj»**.
2. У меню зліва знайдіть розділ **Database** (База даних).
3. Усередині пошукайте підрозділ **Backups** (Резервні копії).
4. Якщо там є кнопка завантаження копії (**Download**) — натисніть її та збережіть файл.

> Цей спосіб доступний не на всіх тарифах Supabase. Якщо розділу **Backups** немає
> або немає кнопки завантаження — переходьте до способу Б (або хоча б обов'язково
> зробіть Excel-експорт заявок із розділу 3 нижче — це врятує найголовніше).

### Спосіб Б — ручний дамп бази (складніший)

«Дамп» (dump) — це один файл, у якому лежить уся база. Він потрібен лише для
відновлення; **відкривати й читати його не треба**.

1. У **supabase.com** → ваш проєкт → відкрийте **Project Settings** (Налаштування,
   значок шестерні) → **Database**.
2. Знайдіть блок **Connection string** (рядок підключення) і скопіюйте варіант
   **URI**. Він має вигляд:
   `postgresql://postgres:ВАШ_ПАРОЛЬ@db.zfblkrrbtiunzndffvyn.supabase.co:5432/postgres`
3. Замість **`ВАШ_ПАРОЛЬ`** підставте пароль бази (той, що ви задавали при створенні
   проєкту; його ж можна скинути на цій самій сторінці кнопкою **Reset database password**).
4. На комп'ютері відкрийте командний рядок і виконайте команду (замініть рядок у
   лапках на свій, з підставленим паролем):

   ```
   pg_dump "postgresql://postgres:ВАШ_ПАРОЛЬ@db.zfblkrrbtiunzndffvyn.supabase.co:5432/postgres" --schema=public --no-owner -f vrk-baza.sql
   ```

5. Поруч з'явиться файл **`vrk-baza.sql`** — це і є копія бази.

> ⚠️ **Увага:** цей спосіб потребує встановленої програми **PostgreSQL** (у ній є
> `pg_dump`). Якщо команда пише «pg_dump не знайдено» — цей спосіб не для вас без
> допомоги розробника. Тоді користуйтеся способом А та Excel-експортом (розділ 3).

**Що вийде:** файл `vrk-baza.sql` (нечитабельний — це нормально, він для відновлення).
Головні таблиці всередині: `leads` (заявки), `lead_comments` (коментарі/нотатки до
заявок), `offline_conversions` і `conversion_adjustments` (конверсії), `site_content`
(тексти сайту, SEO, юр-документи), `site_settings` (налаштування), `tracking_tags`
(теги аналітики), `integrations` (зашифровані ключі), `admin_roles`/`user_roles`
(ролі й доступи адмінів).

## 3. Заявки (ліди) у зручному вигляді (Excel)

**Навіщо:** «людська» копія заявок і конверсій, яку можна відкрити в Excel і читати
очима (на додачу до дампа з розділу 2). **Час:** 2 хвилини.

1. Увійдіть в адмінку сайту (адреса виду `ваш-сайт/admin`) під своїм логіном.
2. У меню зліва відкрийте розділ **Аналітика**.
3. Знайдіть кнопку експорту (**Експорт** / **Вивантажити**) — вона відкриває віконце,
   де можна вибрати період і потрібні колонки.
4. Виберіть потрібний період (наприклад, «за весь час») і натисніть кнопку
   завантаження.
5. Браузер збереже файл **`.xlsx`** (Excel) із заявками та показниками конверсій.

**Що вийде:** таблиця Excel із заявками, цільовими/нецільовими лідами та конверсіями.
Зберігайте її разом з рештою бекапу.

> Порада: робіть цей експорт регулярно — навіть якщо все інше не встигнете, у вас
> завжди буде свіжий список клієнтів у зрозумілому вигляді.

## 4. Файли та зображення (Supabase Storage)

**Навіщо:** картинки, які ви завантажували в адмінці (макети послуг, фото команди,
скріни кейсів, OG-картинка). **Час:** 2–5 хвилин (залежно від кількості файлів).

1. Відкрийте **supabase.com** → ваш проєкт **«vrk proj»**.
2. У меню зліва виберіть розділ **Storage** (Сховище).
3. Відкрийте «кошик» (bucket) з назвою **content**.
4. Виділяйте файли й завантажуйте їх кнопкою **Download** (або через меню «три
   крапки» біля файлу → **Download**).

**Що вийде:** ваші картинки на комп'ютері. Покладіть їх у папку `бекап / зображення`.

> Якщо у сховищі порожньо або є лише кілька файлів — нічого страшного: більшість
> зображень сайту лежать у коді (розділ 1), а тут лише те, що ви довантажували вручну.

---

## 5. Налаштування хостингу (Vercel) — секретні ключі

**Навіщо:** без цих ключів сайт не запрацює на новому місці. **Час:** 3 хвилини.

1. Відкрийте **vercel.com**, увійдіть і виберіть проєкт вашого сайту (той, що
   відкривається як **vrk-partners-nine.vercel.app**).
2. Угорі відкрийте вкладку **Settings** (Налаштування).
3. У меню зліва виберіть **Environment Variables** (Змінні оточення).
4. Ви побачите список змінних (назва + приховане значення). Для кожної натисніть на
   значення, щоб показати його (значок ока або **Show**), і **випишіть назву та
   значення** у надійне місце.

**Що вийде:** список пар «назва = значення» (наприклад, ключі Supabase, Upstash,
секрет шифрування). Збережіть їх у **менеджері паролів**.

> ⚠️ **Увага: це секрети.** Зберігайте їх лише в менеджері паролів (Bitwarden,
> 1Password тощо). **Не** пересилайте поштою, у Telegram чи месенджерах, **не**
> зберігайте у звичайному текстовому файлі на робочому столі.

---

## 6. Таблиця конверсій (Google Таблиці)

**Навіщо:** копія таблиці, куди сайт складає конверсії для Google Ads. **Час:** 1 хвилина.

1. Відкрийте вашу Google-таблицю конверсій (посилання на неї має бути там, де ви його
   зберегли; вона підключена в адмінці в розділі **Інтеграції → Google Sheets**).
2. У меню вгорі натисніть **Файл**.
3. Наведіть на пункт **Завантажити** (Download).
4. Виберіть формат **Microsoft Excel (.xlsx)**.

**Що вийде:** файл Excel із конверсіями. Зберігайте його разом з бекапом.

---

## 7. Налаштування інтеграцій в адмінці (ключі Telegram, KeyCRM, пошти тощо)

**Навіщо:** щоб не втратити доступи до сповіщень і CRM. **Час:** залежить від кількості.

Ці ключі зберігаються в базі **зашифрованими**, тому «скачати» їх у читабельному
вигляді не можна — і не треба. Замість цього **випишіть їх із першоджерел** у
менеджер паролів:

- **Telegram-бот** — токен беруть у бота **@BotFather** у Telegram.
- **KeyCRM** — ключ API у кабінеті KeyCRM.
- **Пошта (SMTP)** — пароль застосунку в акаунті Google.
- **Google Sheets / Google Ads** — доступи в кабінеті Google.

> Детальний перелік усіх доступів і де їх узяти — у файлі **`HANDOVER-checklist.md`**
> у корені репозиторію. Тримайте всі ці ключі в менеджері паролів.

---

## 8. Як часто робити бекап

- **Перед будь-якими великими змінами** на сайті (оновлення, зміна налаштувань).
- **Раз на місяць** — планово.
- Найважливіше — **база даних** (розділ 2) і **Excel-експорт заявок** (розділ 3): там
  ваші клієнти. Якщо часу мало — робіть хоча б це.

## 9. Фінальний чек-лист

Заповнюйте цю таблицю щоразу, коли робите бекап — так ви бачитимете, що не забули.

| Що зберігаємо | Звідки | Що виходить (файл/папка) | Коли завантажено востаннє |
|---|---|---|---|
| Код сайту | GitHub → Code → Download ZIP | `VRKPartners-main.zip` | |
| База даних | Supabase → Database → Backups / `pg_dump` | `vrk-baza.sql` | |
| Заявки в Excel | Адмінка → Аналітика → Експорт | файл `.xlsx` | |
| Файли/зображення | Supabase → Storage → `content` | папка з картинками | |
| Ключі хостингу | Vercel → Settings → Environment Variables | запис у менеджері паролів | |
| Таблиця конверсій | Google Таблиці → Файл → Завантажити → Excel | файл `.xlsx` | |
| Ключі інтеграцій | першоджерела (BotFather, KeyCRM, Google) | запис у менеджері паролів | |

> ⚠️ **Увага:** файл з виписаними секретами й ключами — **не діліться ним** ні з ким і
> зберігайте лише в менеджері паролів.
