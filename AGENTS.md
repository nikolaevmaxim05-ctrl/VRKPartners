# AGENTS.md — правила проекта VRK Partners

Проект перестраивается по стандарту `CLIENT-SITE-BLUEPRINT.md` (корень репозитория):
onion-архитектура + фичи стандарта, поэтапно, in-place, на живом проде. Этот файл —
источник правды по **правилам, отклонениям и решениям**. `CLAUDE.md` содержит строку
`@AGENTS.md` и указывает сюда. Целевая архитектура и карта модулей — `ARCHITECTURE.md`;
схема БД, миграции и переносы данных клиента — `MIGRATION-LOG.md`.

Язык: **UI сайта и админки — только uk-UA**; общение, отчёты и документы — русский.

## Стек (зафиксирован, НЕ апгрейдим в рамках перестройки)

- **Next.js 15.1** App Router, React 19, TS strict. Прокси — **`src/middleware.ts`**
  (НЕ `proxy.ts`). Все упоминания `proxy.ts` из стандарта применяются к `middleware.ts`.
- **Tailwind 3**, **shadcn на Radix** (НЕ Base UI). Селекторы `[data-slot=…]` из
  стандарта (раздел 14) заменяются на реальные селекторы Radix-примитивов проекта.
- **next-intl 4 — внедряем** (профиль **A**: `locales: ['uk']`, `localePrefix: 'never'`,
  адреса без `/uk`). Апгрейды Next 16 / Tailwind 4 / Base UI — **вне** задачи.
- Инструменты, которых сейчас нет и которые добавляются по фазам: ESLint 9 (flat
  config, `eslint-config-next@15.1`), `dependency-cruiser`, `next-intl`,
  `@playwright/test`. Все — devDependencies с точными версиями в lock-файле.

## Отклонения от стандарта (осознанные, с обоснованием)

1. **Стек** — Next 15 / `middleware.ts` / Tailwind 3 / Radix (см. выше).
2. **Вкладка «Метадані (SEO)» остаётся редактируемой из админки.** Стандарт запрещает
   редактировать `pageMeta`. Хранилище — строка `site_content` id=`seo`, модуль
   `lib/seo.ts` → `core/domain/content/seo`. Правило переименования ключей (раздел 9)
   действует и на неё.
3. **Раздел «Юридичні документи»** (Політика конфіденційності / Публічна оферта) —
   нестандартная фича, остаётся. Дефолты — `src/content/legal/*`, правки — строка
   `site_content` id=`legal`, роуты `/polityka-konfidentsiynosti`, `/publichna-oferta`.
   Тексты юр.документов **не** переезжают в `messages/uk.json` (это документы, а не
   тексты интерфейса; у них своя модель «секции»).
4. **Turnstile НЕ внедряем** (решение владельца, подтверждено 2026-09-10). Стандарт
   требует капчу с fail-closed — у нас защита формы: honeypot + rate-limit по таблице
   `leads`. Ключи `turnstile_*`, виджет, серверная проверка, CSP-хосты
   `challenges.cloudflare.com` — не добавляются. Порт `Captcha` в ядре не заводится.
5. **Формат id `site_content`** — оставляем текущие `landing`, `seo`, `legal`
   (стандартный `landing:uk` к данным не применяем — «адаптировать код, не данные»).
   Строка на язык = `landing` для `uk`; при появлении второго языка id новых строк
   будут `landing:<lang>`, а `landing` останется алиасом `uk`.
6. **Имена ключей контента не переименовываем.** Ключи `config/site.ts` переезжают в
   `messages/uk.json` **с теми же именами и той же вложенностью** (`hero.title`,
   `trust.caseGroups[].cases[].metrics[]` …), потому что у клиента есть правки по
   `hero`, `site`, `trust`. Определение типа поля по имени ключа (лимиты длины,
   раздел 9) реализуется таблицей соответствий в одном модуле ядра, а не
   переименованием ключей.
7. **KeyCRM** — четвёртый канал уведомлений (нет в стандарте), остаётся как адаптер
   порта уведомлений. Ключи `keycrm_api_key` (БД→env), `KEYCRM_PIPELINE_ID` (env).
8a. **Вкладка «Телефонія»** (`telephony_secret` в `integrations`, webhook-URL для
   Binotel/Ringostat/UniTalk) — нестандартная фича, остаётся (решение владельца).
8. **Dev-инструмент проверки доставки GA4** (`/api/admin/dev/ga4-arrival`,
   `NEXT_PUBLIC_DEV_TOOLS=1`) — нестандартная фича, остаётся, переезжает в
   `infrastructure/integrations/ga4` + use-case.
9. **RLS строже стандарта**: чтение таблиц с PII разрешено не любому `authenticated`,
   а только активному админу (`is_active_admin()`, миграция 025). Это сохраняем и
   распространяем на все таблицы; стандартный `authenticated_read` без проверки
   активности не применяем.
10. **`leads.ip_address` — тип `inet`** (стандарт: `text`). Не меняем. Значение
    `'unknown'` из IP-цепочки в БД пишется как `NULL`.

## Замены поведения по стандарту (внедряем)

- **Rate limit формы** → подсчёт по таблице `leads` (**3 заявки / 10 мин с одного
  IP**, считаются только валидные, ошибка подсчёта заявку **не блокирует**). Текущий
  механизм `rate_limits` + `check_rate_limit` (миграция 026) и его чистка в keepalive —
  убрать; таблицу и функцию дропнуть миграцией. Upstash уже удалён из кода —
  вычистить остатки из README/`.env.example`.
- **IP-цепочка:** `cf-connecting-ip` → первый `x-forwarded-for` → `x-real-ip` →
  `'unknown'` (раздел 8 стандарта). Заменяет текущую `lib/ip.ts` (там обратный
  порядок и последний сегмент XFF). На Vercel `x-forwarded-for` выставляет платформа,
  клиентский спуфинг невозможен.
- Приём заявки — по порядку раздела 8 (Zod → honeypot → rate limit → нормализация →
  дедуп → запись → уведомления `Promise.allSettled` с `await`), **без** шага капчи.
  Лид пишется **до** уведомлений (сейчас — параллельно с ними).
- **Нормализация телефона — одна функция** (`normalizePhone` → E.164 `+380…`) для
  Zod, дедупа, Enhanced Conversions и выгрузки в Sheets. Текущая вторая функция
  `normalizePhoneE164` в `enhanced-conversions.ts` удаляется. Перед хешем email для
  `gmail.com`/`googlemail.com` убираются точки (раздел 15).
- **Мерж контента** — по правилам раздела 9: «пусто = убрано», массив заменяется
  целиком, чужие ключи игнорируются, дифф рекурсивный. Текущее поведение «пустая
  строка = вернуть дефолт» заменяется кнопкой «До дефолту».

## Процесс (все фазы)

- **Git:** коммиты прямо в `master`, мелкие, с префиксом фазы (`phase1: …`).
  Веток и PR **не** заводим (решение владельца, подтверждено 2026-09-10). Ассистент
  **не пушит**; владелец пушит `git push newrepo master` после подтверждения фазы.
- **Проверки перед коммитом (цель):** `npx tsc --noEmit && npm run lint && npm run
  test && npm run depcheck && npm run build`; с Фазы 6 — `npx playwright test` и
  `node scripts/check-overflow.js`. В песочнице ассистента `build`/e2e могут не
  проходить по времени → ассистент гоняет что успевает и **явно помечает** частичный
  результат; полный прогон — у владельца перед пушем.
- **После каждой фазы — СТОП:** отчёт (что сделано, что перенесено без изменения
  поведения vs что изменилось, результаты проверок, вопросы, план следующей фазы) и
  ожидание «продолжай».
- **Данные клиента неприкосновенны** (лиды, правки `site_content`, `site_settings`,
  ключи `integrations`). Любой перенос/переименование ключей — сначала SQL-проверка
  `select id, jsonb_object_keys(data) from site_content;`, запись в `MIGRATION-LOG.md`
  с SQL проверки и отката, и только потом код.
- **Реестр аналитики и имена событий НЕ менять** (клиентские GTM-триггеры).
  Имена `form_start` / `form_submit` запрещены; успешная отправка = `generate_lead`.
- **Любое изменение схемы БД = файл миграции** `supabase/migrations/NNN_*.sql`,
  идемпотентный. Применяется в прод только после мержа кода в `master`.
- **Формат шифртекста `integrations` (AES-256-GCM, hex `encrypted_value`/`iv`/
  `auth_tag`) не менять** — в БД уже лежат ключи Telegram.
- Ничего клиентского не хардкодить (админка — шаблон-продукт). Тексты сайта — только
  в `messages/uk.json`; тексты админки — в компонентах (uk-UA).
- Конфликт стандарта с кодом, не покрытый решениями выше, — не решать самовольно,
  выносить в отчёт фазы вопросом.

## Фаза 2: принятые решения (подтверждены владельцем 2026-09-11)

1. **`withAdmin([])` требует активную роль.** Раньше 8 GET-роутов (справочники: стадии,
   поля, роли, теги, настройки, пользователи, ответственные, события) пускали любого
   залогиненного, в т.ч. деактивированного. Теперь нужен активный `user_roles` (раздел 5:
   «деактивированный — никаких прав»). Легитимные пользователи не затронуты.
2. **Репозитории читают service-клиентом.** Часть GET раньше шла SSR-клиентом под RLS; теперь
   все запросы — в `infrastructure/supabase/repositories/*` через `service_role`, защита —
   `withAdmin` (права) + middleware (сессия). RLS остаётся вторым рубежом для прямого REST.
3. **Нет права на раздел → редирект на `/admin`** (было `/admin/leads`); `/admin` пока
   перенаправляет на аналитику/лиды, в Фазе 5 станет главной с карточками.
4. **middleware: `/api/admin/*` без сессии → 401 JSON** (раздел 16). Раньше это делал
   каждый роут сам; dev-роут GA4 без сессии теперь отвечает 401, а не 404.
5. **Канонический приёмник — `/api/leads`**, `/api/lead` — алиас (решение 19). Форма
   переключается на `/api/leads` в Фазе 4 вместе с новым порядком проверок.
6. **Раскладка папок по разделу 4** внутри `src/`: `components/ui`→`shared/ui`,
   `components/admin`→`features/admin/components`, лендинг →
   `features/landing/components/{sections,forms,layout,ui,legal}`, `config`→`shared/config`,
   `content/legal`→`shared/content/legal`, `hooks`→`shared/hooks`; `src/lib` растворён
   (серверное — в `infrastructure`/use-cases, клиентское — в `shared/lib` и `features/*/lib`).
7. Лог `[lead] rl_headers` пишется для каждого запроса с валидным JSON (раньше — после Zod).

## Фаза 3: принятые решения (подтверждены владельцем 2026-09-11)

1. **Тексты сайта — только `src/messages/uk.json`** (дефолты) ⊕ правки клиента в

   (`hero.badge/formTitle`, `services.eyebrow`, `audit.eyebrow/formTitle/services`,
   `trust.eyebrow/cta`, `workflow.eyebrow/cta`, `finalCta.eyebrow/telegramCta`, `site.legalName/
   tagline/format`, `workflow.steps[].n`, `about.members[].key`, справочники `adFormats/
   budgetRanges/goals`). У клиента есть правки по `trust.eyebrow` и `trust.cta` — они равны
   дефолтам и никогда не рендерились; мерж их игнорирует (MIGRATION-LOG.md, раздел 4).
   **2026-09-13:** блок «Ніші» в левой колонке кейсов (подпись + чипы) убран по решению владельца;
   ключи `trust.nichesTitle`/`trust.niches` удалены из дефолтов, типа и редактора по тому же правилу;
   у клиента правок по ним нет (SQL-проверка в MIGRATION-LOG.md), мерж чужие ключи игнорирует.
   Переключатель ниш в карточке кейсов (`nicheStep`, `nichesAria`, `caseGroups[].niche`) не тронут.
2. **Рендер текстов — через `useMessages()`/`getMessages()`, а не `t('key')`.** Тексты
   редактирует клиент, и ICU-синтаксис (`{`, `'`) в них — обычные символы, а не формат;
   структурные блоки (карточки, кейсы) — массивы объектов, которые `t()` не отдаёт.
   Типы — `core/domain/content/site-messages.ts` (явные, из-за необязательных полей).
3. **Профиль A по разделу 10:** `app/[locale]/` + `localePrefix: 'never'`, middleware
   пропускает через next-intl только страницы сайта (не `/admin`, не `/api`, не файлы).
   `<html lang>` ставится в корневом layout из единой карты `LOCALE_CODES` (root layout
   общий с админкой, которая вне языков). `alternateLinks/localeDetection/localeCookie`
   выключены (одна мова).
4. **Мерж/дифф по разделу 9** (`core/domain/content/messages.ts`): «пусто = убрано», массив
   целиком, чужие ключи игнорируются, дифф рекурсивный. Старый формат правок клиента
   читается без миграции (тест `shared/content/__tests__/defaults.test.ts`). Пересчёт
   диффа (MIG-CONTENT-01) — гигиена по подтверждению.
5. **Лимиты по типу поля** (`core/domain/content/limits.ts`): признаки таблицы раздела 9
   применяются к camelCase-именам как суффиксы (`modalDescription` → абзац, `primaryCta` →
   кнопка); исключения — `FIELD_TYPE_EXCEPTIONS` (напр. `faq[].q` → заголовок, `hero.trust` →
   абзац, `partnerLinkText` → подпись). Один модуль на сервер (400 с путём поля) и на редактор
   (счётчик «N / ліміт»). Технические ключи элементов `key`/`id` не показываются, но хранятся.
6. **Скрытие блоков** (`core/domain/content/visibility.ts`): `HIDEABLE_BLOCKS.home` = секции
   (`hero, usp, about, services, audit, cases, process, faq, finalCta`), список — `home.hidden`.
   Элементы списков (карточки, кейсы, шаги) **не** имеют своих id для скрытия: списки
   редактируются (добавить/удалить), поэтому «скрыть карточку» = удалить её из списка.
   Скрытое не попадает в DOM; ссылки меню/футера на скрытый блок не выводятся. «Про нас»:
   дефолт `hidden: []`, скрытие — правка клиента в БД (MIG-CONTENT-02, решение 5).
7. **Редактор** (`features/admin/components/content-editor.tsx`) — один универсальный,
   строится по `CONTENT_PAGES/PAGE_BLOCKS/KEY_LABELS` (`core/domain/content/layout.ts`) и форме

   смена брейкпоинта) и пишется в CSS-переменную `--services-window = 1.5 × card + gap`; CSS-фолбэк

   Карточки в дефолтном контенте: первая 325 px, остальные 302 px — окно считается по первой.
3. **Свободная прокрутка без snap** (решение владельца) и **нативный scroll chaining**
   (`overscroll-behavior: auto`): на краях окна прокрутка передаётся странице.
4. **Индикаторы** (уточнение владельца 2026-09-12: края растворяются в фон, как у ленты партнёров).
   Затухание сверху/снизу — **маска самого скроллера**, а не накладки цветом страницы (накладки `from-bg`
   поверх аврора-фона читались как чёрная полоса): класс `.services-window` в `globals.css`, `< sm`,
   `mask-image` + `-webkit-mask-image` = `linear-gradient(to bottom, transparent, black var(--fade-top),
   black calc(100% − var(--fade-bottom)), transparent)`, зона 2.5rem (`--services-fade`). Выбран
   **вариант B — переключаемая маска** (геометрия окна не меняется): на краю соответствующая зона = 0
   (`[data-at-start="1"] > .services-window { --fade-top: 0 }`, аналогично `at-end`; атрибуты на обёртке
   пишутся из scroll → rAF), плавность — `@property --fade-top/--fade-bottom` (`<length>`) + `transition`
   300 мс (Chromium, Safari 16.4+, Firefox 128+; без `@property` — мгновенно). Без JS: `at-start=1` →
   сверху маски нет, снизу есть. Маска касается только скроллера: полоска-прогресс справа — сосед в
   обёртке, вне маски (трек 2px, бегунок — высота `clientH²/scrollH`, позиция `transform: translate3d`;
   окно имеет `pr-3`, чтобы полоска не перекрывала контент; при отсутствии прокрутки скрыта
   `data-scrollable=0`). Reduced motion: маска остаётся (не движение), переход гасится общим правилом.
5. **Доступность:** `role="region"`, `aria-label` = `services.title`, `tabIndex={0}` (клавиатурная
   прокрутка нативная), `data-items` на окне. **Focus-ring — на обёртке** (`.services-wrap:has(> …:focus-visible)`,
   те же классы, что `btn-focus`): маска обрезает box-shadow самого скроллера. `reveal-stagger` остался на окне
   (RevealObserver наблюдает контейнер, дети получают `is-visible` с задержками — «пустых» карточек нет).
6. **Reduced motion:** затухание и полоска остаются (не движение), переходы гасятся общим правилом.
7. **e2e-хелпер `overflowingElements`** считает клипающими и контейнеры с `overflow: auto|scroll`.
8. **Не проверено на реальных устройствах:** поведение вложенной прокрутки в iOS Safari и Android
   Chrome (эмуляция Chromium проходит; маска краёв проверена и в Playwright WebKit); владелец тестирует
   сам. Известный риск WebKit: маска на прокручиваемом контейнере в старых iOS могла прокручиваться
   вместе с контентом — проверить на устройстве.

### Шаг 3b — лайтбокс картинок услуг на тач (подтверждено владельцем 2026-09-12)

1. **Условие показа:** там, где не совпадает `PREVIEW_MEDIA` = `(hover: hover) and (min-width: 640px)`
   (тач или `< sm`). Определяется после гидрации (`matchMedia` + change): SSR рендерит миниатюру как
   `div`, на тачи она становится `<button data-zoom-trigger>` с иконкой `ZoomIn` в углу. На десктопе с
   hover клик по миниатюре ничего не открывает, hover-превью без изменений.
2. **Новый ключ `services.zoomLabel`** («Збільшити зображення») — `uk.json`, тип
   `ServicesMessages`, `KEY_LABELS` и перечень ключей редактора; `aria-label` кнопки =
   `«{zoomLabel}: {name}»`. Крестик лайтбокса использует существующий `form.closeLabel`.
3. **`ImageLightbox`** (`features/landing/components/ui/ImageLightbox.tsx`, на примитивах Dialog):
   `fixed inset-0 z-[100] bg-black/90`, картинка `mockupFull ?? mockup` через `next/image fill
   object-contain sizes=100vw`, крестик 44×44 с тёмным фоном (виден на белых скриншотах), закрытие
   крестиком / Escape / тапом по фону вне картинки, фокус на крестик при открытии и возврат на
   кнопку-триггер, `aria-modal`, `aria-label={name}`, блокировка прокрутки body, fade 200 мс.
   **Рендерится порталом в `document.body`** (с 2026-09-12, вместе с маской окна услуг): в DOM лайтбокс
   лежит внутри скроллера, а `mask-image` создаёт stacking context — без портала `fixed`-слой оказывался
   под шапкой (`z-50`) и обрезался маской.
4. **Щипок — свой, без библиотек** (решение владельца: нативный щипок масштабировал бы весь вьюпорт
   и оставлял страницу увеличенной после закрытия; `<meta viewport>` не менялась): pointer events,
   щипок 1×–4× относительно точки между пальцами, двойной тап по картинке 1× ↔ 2.5× с приближением к
   точке тапа, перетаскивание одним пальцем при увеличении с ограничением по краям картинки; всё через
   `transform` без ре-рендеров; `preventDefault` на pointerdown (фокус остаётся на крестике).
5. **Аналитика:** новых событий нет (реестр не менялся).
6. **Не проверено на реальных устройствах:** срабатывание тапа внутри вложенной прокрутки iOS и
   щипок в Safari (эмуляция CDP в Chromium проходит).

### Шаг 4 — разгорание слов в Audit (подтверждено владельцем по ходу, 2026-09-12)

1. **Техника — только JS на rAF, нативная прокрутка не подменяется** (решение владельца: без
   locomotive/lenis/gsap, без CSS `animation-timeline: view()` — правило конца страницы и сдвиг
   внутри строки в чистом CSS не выражаются, второй путь для iOS < 26 не нужен). Разметка —
   `shared/lib/split-words.tsx` (`SplitWords`: слова в `<span data-word>`, пробелы — текстовые узлы,
   NBSP/дефисы внутри слова; `textContent` пункта = исходной строке). Правило —
   `core/domain/layout/word-reveal.ts` (`wordOpacity`, `readingLineY`, `splitWords`, юнит-тесты).
   DOM — `features/landing/lib/word-reveal.ts`: позиции слов кэшируются один раз (top в документе,
   доля left в строке), пересчёт на resize / `fonts.ready` / ResizeObserver контейнера / смену маршрута;
   scroll → passive + rAF → арифметика по кэшу и запись `style.opacity` при изменении ≥ 0.02;
   IntersectionObserver-гейт (запас 50 % высоты окна). Инициализатор `WordReveal` в layout сайта
   ищет все контейнеры `[data-word-reveal]` — эффект переносится в другие блоки атрибутом на
   контейнере + `SplitWords` в тексте.
2. **Константы** (`WORD_REVEAL_DEFAULTS`, стартовый «мягкий» вариант; финальные значения владелец
   подбирает на проде): линия чтения **0.72 vh** (уточнение владельца 2026-09-12, было 0.6; чуть ниже
   центра, ближе к низу экрана), **минимум 0 — слова до линии полностью невидимы**
   (уточнение владельца 2026-09-12; панель `/?tune-words=1` допускает 0…0.9), смуга 0.14 vh,
   сдвиг в строке 0.06 vh.
   Конец страницы: на последних `(1 − 0.6)·vh` пикселях прокрутки линия опускается до
   `vh + сдвиг·vh` → при максимальной прокрутке яркое всё, что в окне. Прокрутка назад — чистый скраб
   по позиции (слова тускнеют обратно, без «запоминания»).
3. **Что разгорается (уточнение владельца 2026-09-12): весь текст карточки** — название (h3),
   описание («Ми аналізуємо:») и пункты списка; порядок задаётся геометрией (линия идёт сверху вниз).
   Галочка `[data-word-check]` получает opacity первого слова пункта. Иконка карточки — не текст,
   всегда видима; высота карточек не меняется (невидимые слова занимают место). Заголовок секции
   (h2 с FitText/nbHyphen) — **не** участвует (решение владельца). Эффект на всех ширинах.
4. **`reveal-stagger` в секции Audit убран** (решение владельца: выезд карточек поверх скраба слов —
   перегруз); заголовок секции остаётся с `.reveal`; hover-scale карточек на десктопе оставлен.
5. **Сглаживание** — transition opacity 100 мс linear на словах и галочках (решение владельца).
6. **Reduced motion:** JS не подключает эффект (при смене настройки на лету снимает инлайн-стили и
   класс `js-word-reveal`); страховочное правило в общем блоке `globals.css` — все слова и галочки
   `opacity: 1`. Без JS — инлайн-стилей и класса нет, всё яркое.
6a. **Скрытие до гидрации (решение владельца 2026-09-12):** инлайн-скрипт в `app/[locale]/layout.tsx`
   (до разметки сайта, CSP уже разрешает `unsafe-inline`) ставит на `<html>` класс `js-word-reveal`,
   если нет `prefers-reduced-motion`; CSS `.js-word-reveal [data-word-reveal] [data-word]` → `opacity: 0`
   до первого расчёта; JS пишет явную «1»/значение в инлайн-стиль, при отключении снимает класс.
   Без этого на проде с медленной гидрацией текст при загрузке `/#audit` был бы виден ярким, а потом
   исчезал (локально окно яркости 0–53 мс, с инлайном — 0 мс). Риск принят: при сбое гидрации текст
   в этих контейнерах остаётся скрытым.
7. **Временная панель подбора** `WordRevealTuner` (в layout): появляется только по адресу
   `/?tune-words=1` (флаг в localStorage браузера; `/?tune-words=0` выключает и очищает), четыре
   ползунка, значения применяются на лету, посетители её не видят. **Удалить** (файл + подключение в
   layout + событие `WORD_REVEAL_PARAMS_EVENT`) после того, как владелец подберёт значения на проде
   и они будут зашиты в `WORD_REVEAL_DEFAULTS`.
8. Замер (390×844, 63 слова, скролл через секцию): CPU ×1 — 60 fps без пропусков; CPU ×4 — p95
   16.8–33 ms, 4–8 кадров > 20 ms из ~140 (в основном при входе секции в окно). Стресс-контент
   (пункты по ~500 символов, ~2000 слов) — e2e stress.spec проходит.

### Шаг 5 — автоувеличение скриншота кейса на мобильных + лайтбокс (подтверждено владельцем по ходу, 2026-09-14)

1. **Автоувеличение (< 640px)** — скраб по позиции: чем ближе центр скриншота к центру экрана, тем
   больше масштаб, до полной ширины вьюпорта; назад — обратный ход. Правило —
   `core/domain/layout/case-image-zoom.ts` (юнит-тесты): целевой масштаб `S = min((vw − 2px) /
   width, 1.6)`, прогресс `1 − |centerY − vh/2| / (0.35·vh)`, сглаживание smoothstep,
   `scale = 1 + (S − 1)·smoothstep(p)`; плато у центра не вводилось (владелец принял без него).
   DOM — `features/landing/lib/case-image-zoom.ts`: подключается из `Trust.tsx` эффектом на
   `[nicheIdx, caseIdx]` (блок кейса перемонтируется по `key`, инициализатор в layout не нужен);
   геометрия через `offsetTop/offsetHeight` (rect масштабированной обёртки врал бы), кэш; пересчёт на
   resize / ResizeObserver обёртки **и `body`** (контент выше секции досчитывается после гидрации и
   сдвигает обёртку без изменения её размера) / IntersectionObserver при подходе к вьюпорту /
   `fonts.ready` / загрузка картинки; scroll → passive + rAF → `transform: scale()` на обёртке
   `[data-case-zoom]`, запись при изменении ≥ 0.002; `data-zoomed="1"` при масштабе > 1 →
   `z-index: 10`, `will-change`, мягкая тень на внутреннем блоке (`globals.css`).
2. **Вёрстка:** увеличенная картинка перекрывает рамку карточки (никакой предок не режет её
   `overflow: hidden`; на секции `#cases` для `< sm` — `overflow-x: clip` как страховка от
   горизонтального скролла: clip, не hidden — не создаёт скролл-контейнер, якорь `scroll-margin`
   работает). **Запас по вертикали** (решение владельца — оставить): `--case-zoom-reserve =
   (S − 1)·h / 2` от JS → `margin-top: calc(1.25rem + reserve)`, `margin-bottom: reserve` (≈ 11 px на
   390, карточка выше на ~22 px), чтобы картинка не наезжала на метрики и «Підходи». Скругление, рамка,
   белый фон сохранены. Проверено: на 320/360/390/430 в центре картинка касается краёв (1 px запас),
   `document.scrollWidth === innerWidth`; 1440 — без transform.
3. **Лайтбокс (решение владельца — на всех устройствах, у кейсов нет hover-превью):** картинка после
   гидрации — `<button data-zoom-trigger>` с иконкой `ZoomIn` (SSR — div), тап/клик открывает
   `ImageLightbox` (портал, щипок, двойной тап, перетаскивание) с `src = cur.image`; `aria-label` =
   `«{services.zoomLabel}: {client}»` — **ключ переиспользуется** (решение владельца, отдельный
   `trust.zoomLabel` не заводился). Тап по увеличенной картинке работает (кнопка масштабируется вместе
   с обёрткой, transform портала не касается).
4. **Деградация:** без JS — картинка как раньше (нет `--case-zoom-reserve`/transform, div вместо
   кнопки); `prefers-reduced-motion: reduce` — JS не подключает эффект (при смене на лету — сброс),
   страховка `.case-zoom { transform: none }` в общем reduced-motion блоке; лайтбокс работает.
5. **Аналитика:** новых событий нет.
6. **e2e** `tests/e2e/case-image.spec.ts` (контент — дефолтные `trust.caseGroups` через
   `E2E_CONTENT_OVERRIDES`, герметично к правкам клиента): 390 — масштаб ≈ (vw − 2)/width, ширина ≈ vw,
   без горизонтального скролла, вне зоны 1, смена кейса, лайтбокс (крестик/Escape/фон, фокус),
   reduced motion; 1440 — transform нет, клик открывает лайтбокс. Переключение кейса в тесте —
   программным `click()` (после прокрутки кнопки ниш под фиксированной шапкой).
7. **Не проверено на реальных устройствах:** плавность масштабирования при инерционной прокрутке iOS
   и срабатывание тапа по масштабируемой кнопке в Safari (эмуляция Chromium/CDP проходит).
