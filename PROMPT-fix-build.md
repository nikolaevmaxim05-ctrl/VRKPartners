# Задача: починить упавший Vercel-деплой (commit eb97bb4) и 17 красных тестов

Деплой на Vercel упал, локально `npm run build` проходит, но `npm test` — 17 фейлов. Ниже разбор причин; проверь каждую гипотезу по коду и почини.

## Проблема 1 — Vercel build падает (главное)

Ошибка на Vercel:

```
./src/app/api/lead/route.ts:17:10
Type error: '"@/lib/integrations/get-integration"' has no exported member named 'prefetchIntegrations'. Did you mean 'getIntegration'?
```

При этом ЛОКАЛЬНО билд проходит без этой ошибки. Это значит: локальная версия `src/lib/integrations/get-integration.ts` содержит `prefetchIntegrations`, а в коммите `eb97bb4`, который ушёл на GitHub — нет. Почти наверняка при коммите «feat(contacts)…» файл get-integration.ts (правка из задачи C12 — батч-чтение integrations) не попал в коммит, либо попал частично.

Действия:
1. `git status` и `git diff HEAD` — найти незакоммиченные/неотслеживаемые изменения (в первую очередь `src/lib/integrations/get-integration.ts`, возможно и другие файлы из C12-правки).
2. Убедиться, что `prefetchIntegrations` реально экспортируется и типы сходятся (`npx tsc --noEmit`).
3. Закоммитить недостающее ОТДЕЛЬНЫМ коммитом с понятным сообщением (например, `fix(build): add missing prefetchIntegrations export (C12 leftover)`), не смешивая с фиксом тестов.

## Проблема 2 — 17 красных тестов в src/lib/integrations/__tests__ (telegram, email, keycrm)

Паттерн одинаковый во всех трёх файлах: тесты, которые задают валидную конфигурацию, всё равно получают `ok:false, error:"not configured"`, а в stderr — «bot_token or chat_id is not set (DB + env) — skipping» и т.п. То есть модули интеграций больше не видят конфиг, который мокают тесты.

Вероятная причина: правка C12 (батч-чтение конфигурации `prefetchIntegrations` / кэш вместо пофайловых `getIntegration`) поменяла путь получения конфига в telegram.ts / email.ts / keycrm.ts, а тесты всё ещё мокают старый путь (env-переменные или старый `getIntegration`). Разберись, как именно модули теперь читают конфиг, и приведи всё к согласованному виду:

1. Сохрани контракт поведения: конфиг из БД (integrations/site_settings) имеет приоритет, env — fallback, при отсутствии обоих — `ok:false` + console.warn, без выброса исключений (это важно для Promise.allSettled в /api/lead — лид не должен теряться).
2. Почини тесты под новый механизм: замокай новый источник (prefetchIntegrations/кэш/клиент Supabase) так, чтобы тестировались те же сценарии, что и раньше (валидный вызов, payload, fallback From, ошибки сети, non-OK статусы, экранирование HTML). НЕ ослабляй ассерты и не удаляй тесты.
3. Если окажется, что дело не в моках, а модули действительно потеряли env-fallback или кэш «залипает» между вызовами (стейл-конфиг между тестами/запросами) — чини сам модуль, а не тесты. Обрати внимание на сброс кэша между тестами (beforeEach) и на TTL/инвалидацию кэша в проде: после смены настроек интеграции в админке новый сабмит должен использовать свежие значения (или TTL должен быть коротким).

## Заодно проверь (не блокер, быстро)

- В локальном билде на этапе Collecting page data сыпется `[marketing/layout] tracking_tags_unavailable / analytics_events_unavailable: Error: supabaseUrl is required.` — это отсутствие env при статической генерации; убедись, что это осталось fail-safe (лендинг рендерится с дефолтами) и лог не превращается в исключение. Ничего не менять, если это ожидаемое поведение без .env — но если supabase-клиент создаётся на верхнем уровне модуля и валится ДО fail-safe ветки, перенеси создание внутрь try.
- Warning `prefetchIntegrations is not exported` в НАЧАЛЕ локального билда из лога компиляции — после фикса Проблемы 1 должен исчезнуть; проверь, что предупреждений об импортах в билде больше нет.

## Порядок и проверка

1. Сначала Проблема 1 (разблокирует деплой), отдельный коммит.
2. Потом Проблема 2, отдельный коммит.
3. Финальная проверка: `npx tsc --noEmit` чистый; `npm run build` без ошибок И без warning'ов об импортах; `npm test` — все 293+ теста зелёные; `git status` чистый (ничего не забыто в рабочей копии).
4. В отчёте: что именно не попало в eb97bb4, чем была вызвана поломка тестов (моки vs реальная регрессия), и подтверждение, что env-fallback и fail-safe поведение интеграций сохранены.
